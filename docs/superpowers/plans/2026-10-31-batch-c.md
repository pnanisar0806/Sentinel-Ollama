# Batch C — Holding Rules and Life Events Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The owner can state per-holding rules the advisor obeys everywhere (with one-off exceptions), and log life events that leave a signed review list and flag IPS stop-events.

**Architecture:** Four append-only tables (migration 0042). `src/domain/holding-rules.ts` owns rule logic and one pure check, `ruleBlock`, called from every place that proposes money into or out of a holding: the recommendation gate, the order gate, SIP suggestions, the switch check, index-fund picks, exit candidates, lump-sum sizing. `src/domain/life-events.ts` owns events, rail/constant review lines and stop-events; goal review lines live in `web/lib/life-events.ts` only (the normal plan never reads goal status).

**Tech Stack:** TypeScript, Postgres (PGlite in tests), vitest, Next.js app router (`web/`).

**Spec:** `docs/superpowers/specs/2026-10-31-batch-c-design.md` — read it in full before any task.

## Global Constraints

- Every new table: append-only (`sentinel_append_only()` triggers for UPDATE/DELETE and TRUNCATE), RLS enabled with no policy, `as_of timestamptz not null`, `source text not null check (source <> '')`; owner rows use `source = 'owner-web'`. Pattern: `migrations/0041_lump_sums.sql`.
- Money is `bigint` paise; percentages are integer bps. Never a float.
- Ending a rule, an exception or an event early is a `log_reversals` row (`src/domain/reversals.ts`), never an edit.
- `src/domain/**` must never import `goal-plan.ts`, `funded-status.ts` or read bucket targets for these features (`tests/architecture/no-catch-up.test.ts`).
- No rule ever changes a rail or an assumption by itself; no automatic SIP pause.
- UI reuses `web/lib/ui.tsx` primitives and the `.tabs` / `.tabs-sm` pill style (`web/app/globals.css`); design against `design-system/sentinel/MASTER.md`.
- An empty list says why it is empty; a null renders `—` or `unknown`, never `0`/`₹0`.
- Rule refusal copy names the rule: `your <KIND label> rule on <fund name>` with KIND labels `NO_ADD` → "no new money", `HOLD_UNTIL` → "hold until <Mon YYYY>", `NO_REBUY` → "never buy again", `CAP_PCT` → "cap at <N>%".
- Interfaces in briefs are authoritative over any illustrative snippet; `Db` is as described in `MEMORY.md` § Contracts.

## Review Focus

1. A rule stored on a seed id (`MF:*`, `NSE:*`) must still bind the live `IND:*` holding — match via `fundAliases`/`sameFund`, never raw id equality. (Task 2 test `binds through aliases`.)
2. An exception scoped to month M must not leak into M+1, and one scoped to a lump sum must not apply to monthly advice. (Task 2 test `exception scope`.)
3. A `CAP_PCT` buy when the portfolio total is unknown must refuse ("cap unknown"), not pass. (Task 2 test `cap unknown refuses`.)
4. A `HOLD_UNTIL` whose date has passed (IST) is inactive the next IST day, not the next UTC day. (Task 2 test `until is IST`.)
5. A reversed rule stops binding immediately, including an exception on it. (Task 2 test `reversed rule inactive`.)

  - `ruleLabel(r: Pick<HoldingRule,'kind'|'untilOn'|'capBps'>): string` — the Global Constraints labels.
  - `ruleBlock(rules: HoldingRule[], q: { aliases: string[]; action: 'BUY' | 'SELL'; amountPaise: bigint | null; heldPaise: bigint; portfolioPaise: bigint | null; month: string; lumpSumId: string | null }): { rule: HoldingRule; reason: string; waivedBy: string | null } | null` — pure. Returns the first breaking rule; if an exception on it covers `month` (when `lumpSumId` null) or `lumpSumId`, returns `{ …, reason, waivedBy: exceptionId }` instead of blocking — callers treat `waivedBy !== null` as allowed and record it. Rules: BUY breaks `NO_ADD` always; `NO_REBUY` when `heldPaise === 0n`; `CAP_PCT` when `portfolioPaise === null` (reason "cap unknown — portfolio total unknown") or `(heldPaise + (amountPaise ?? 0n)) * 10000n > capBps * portfolioPaise`. SELL breaks `HOLD_UNTIL`. Reason: `"your <label> rule on <name>"`.
